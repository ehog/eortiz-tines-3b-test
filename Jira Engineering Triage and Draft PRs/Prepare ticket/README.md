Shared intake for poll batches, existing Jira webhook deliveries, and synthetic replays. Parses HTTP or JSON envelopes and emits one ticket plus a remaining queue. The self-link drains that queue while Triage receives the current ticket; terminal errors reach Report outcome.

The attached Jira connector reads `/rest/api/3/issue/{key}`, its `/comment` endpoint, and bounded linked-issue details. It rechecks the KAN project and `agent-ready` label against the authoritative issue before enrichment. The poller's JQL additionally excludes Done status-category issues; this step does not independently enforce that status restriction for direct/webhook intake. Missing labels or project mismatch are skipped. Description, explicit acceptance criteria, comments and linked issues are bounded; incomplete evidence goes to human review.

Exclusive state reservation deduplicates Jira keys and synthetic replay IDs. Jira keys process once, not once per update. Current configuration uses `sourceMode=jira`, `liveWrites=false`, and empty repository mappings, so Jira tickets are enriched for triage/human review without repository work or Jira changes. Synthetic fixtures still work independently of source mode.

[settings.json](settings.json) is canonical; synchronize it using [sync-config.sh](sync-config.sh). Fixtures are explicitly synthetic in [fixtures.json](fixtures.json).
